# Wireframes - Dessiner Avant de Construire

## Introduction

**WIREFRAME** = Plan bleu = Dessin structural de l'interface

Imagine que tu veux construire une maison. Est-ce que tu commences directement par poser les briques ? Non ! D'abord tu fais un **plan**. Le wireframe, c'est exactement ça : un plan de ton interface avant de la construire.

### Analogie Madagascar 🇲🇬

Pense aux **maçons de Tana** qui construisent une maison :

1. D'abord ils dessinent le plan sur le sol
2. Ils montrent où seront les murs, les portes, les fenêtres
3. Ensuite seulement ils commencent à construire
4. Les finitions (peinture, décoration) viennent à la fin

Le wireframe = Le plan sur le sol, avant les briques !

## Pourquoi faire des Wireframes?

### 1. Gagner du temps

```
❌ SANS WIREFRAME :
Designer → Coder → Tester → Tout changer → Re-coder → Re-tester...
Temps perdu : BEAUCOUP

✅ AVEC WIREFRAME :
Dessiner → Valider → Designer → Coder → Tester
Temps gagné : ÉNORME
```

### 2. Éviter les malentendus

Un wireframe permet à tout le monde de **voir la même chose** :
- Le client voit la structure
- Le designer voit les zones
- Le développeur voit les composants
- Tout le monde est d'accord AVANT de coder

### 3. Se concentrer sur la structure

Sans les couleurs et les images, on peut se focaliser sur :
- La **hiérarchie** de l'information
- Le **placement** des éléments
- La **navigation** entre les pages
- L'**expérience** utilisateur

### 4. Itérer rapidement

Changer un wireframe = 2 minutes
Changer un design final = 2 heures
Changer du code = 2 jours

Plus tôt tu changes, moins ça coûte !

## Les 3 Niveaux de Wireframes

### Niveau 1 : Low-Fidelity (Basse Fidélité)

**Caractéristiques :**
- Dessiné à la main ou rapidement
- Formes simples (rectangles, lignes)
- Pas de détails visuels
- Focus sur la structure

**Quand l'utiliser :**
- Au début du projet
- Pour brainstormer en équipe
- Pour explorer plusieurs options rapidement

```
┌─────────────────────────────────┐
│  [Logo]          [Menu] [Menu]  │
│  ─────────────────────────────  │
│  ┌───────────────────────────┐  │
│  │                           │  │
│  │    [Image Placeholder]    │  │
│  │                           │  │
│  └───────────────────────────┘  │
│                                 │
│  _____Titre_____                │
│  _____Texte_____                │
│  _____Texte_____                │
│                                 │
│  [Bouton]                       │
└─────────────────────────────────┘
```

### Niveau 2 : Mid-Fidelity (Moyenne Fidélité)

**Caractéristiques :**
- Créé sur ordinateur (Figma, Sketch)
- Tailles et proportions réalistes
- Quelques détails (icônes, texte exemple)
- Toujours en noir et blanc/gris

**Quand l'utiliser :**
- Après validation du low-fi
- Pour présenter au client
- Pour guider le développement

### Niveau 3 : High-Fidelity (Haute Fidélité)

**Caractéristiques :**
- Très proche du design final
- Couleurs et images réelles
- Interactions simulées
- Presque un prototype

**Quand l'utiliser :**
- Pour les tests utilisateurs
- Pour la documentation finale
- Quand le client veut "voir" le résultat

⚠️ **Attention** : High-fi trop tôt = perte de temps si la structure change !

## Les Éléments d'un Bon Wireframe

### 1. Layout (Disposition)

Comment les éléments sont organisés sur la page :

- **Header** : En-tête (logo, navigation)
- **Hero** : Section principale visible en premier
- **Content** : Zone de contenu principal
- **Sidebar** : Barre latérale (optionnelle)
- **Footer** : Pied de page (contact, liens)

### 2. Navigation

Comment l'utilisateur se déplace :

- Menu principal
- Breadcrumbs (fil d'Ariane)
- Boutons d'action
- Liens internes

### 3. Hiérarchie Visuelle

Qu'est-ce qui est important ?

- **Grand** = Important
- **En haut** = Important
- **Centré** = Important
- **Petit/En bas** = Moins important

### 4. Call-to-Action (CTA)

Les boutons qui poussent à l'action :

- "Acheter maintenant"
- "S'inscrire"
- "En savoir plus"
- "Contacter"

## Les Outils pour créer des Wireframes

### Outil 1 : Papier et Crayon 📝

**Avantages :**
- Le plus rapide
- Gratuit
- Favorise la créativité
- Facile à jeter et recommencer

**Inconvénients :**
- Difficile à partager
- Pas modifiable facilement

**Conseil :** Toujours commencer par le papier !

### Outil 2 : Figma 🎨

**Avantages :**
- Gratuit (version de base)
- Collaboratif en temps réel
- Facile à transformer en design final
- Composants réutilisables

**Inconvénients :**
- Nécessite un apprentissage
- Besoin d'internet

**Conseil :** L'outil standard de l'industrie !

### Outil 3 : Balsamiq 🖥️

**Avantages :**
- Style "dessiné à la main"
- Très facile à utiliser
- Bibliothèque d'éléments prête

**Inconvénients :**
- Payant
- Style limité

### Outil 4 : Papier + Téléphone 📱

**Technique du paper prototype :**
1. Dessine tes écrans sur papier
2. Photographie-les avec ton téléphone
3. Utilise une app comme Marvel ou POP
4. Crée un prototype cliquable !

**Parfait pour tester rapidement !**

## Comment créer un Wireframe (Méthode pas à pas)

### Étape 1 : Définir le but de la page

**Questions à se poser :**
- Quelle est la page ? (Accueil, Produit, Contact...)
- Quel est l'objectif principal ?
- Que doit faire l'utilisateur ?

**Exemple :** Page d'accueil d'une app de livraison de repas
- Objectif : Faire commander l'utilisateur
- Action principale : "Commander maintenant"

### Étape 2 : Lister le contenu nécessaire

**Pour notre page de livraison :**
- Logo
- Barre de recherche (restaurant, plat)
- Catégories (pizza, burger, asiatique...)
- Restaurants populaires
- Promotions
- Bouton "Commander"

### Étape 3 : Établir la hiérarchie

**Du plus important au moins important :**
1. Barre de recherche (pour trouver)
2. Promotions (attirer l'attention)
3. Restaurants populaires (inspirer)
4. Catégories (explorer)
5. Footer (informations)

### Étape 4 : Dessiner les blocs

Commencer par les grandes zones :

```
┌─────────────────────────────────────────────────┐
│ HEADER                                           │
│ [Logo]              [Recherche]     [Panier]    │
├─────────────────────────────────────────────────┤
│ HERO - Promotion du jour                         │
│ ┌─────────────────────────────────────────────┐ │
│ │      🍕 -50% sur votre première commande    │ │
│ │           [Commander maintenant]            │ │
│ └─────────────────────────────────────────────┘ │
├─────────────────────────────────────────────────┤
│ CATÉGORIES                                       │
│ [Pizza] [Burger] [Asiatique] [Local] [Dessert]  │
├─────────────────────────────────────────────────┤
│ RESTAURANTS POPULAIRES                          │
│ ┌───────┐ ┌───────┐ ┌───────┐ ┌───────┐        │
│ │ Resto │ │ Resto │ │ Resto │ │ Resto │        │
│ │   1   │ │   2   │ │   3   │ │   4   │        │
│ └───────┘ └───────┘ └───────┘ └───────┘        │
├─────────────────────────────────────────────────┤
│ FOOTER                                           │
│ À propos | Contact | Aide                        │
└─────────────────────────────────────────────────┘
```

### Étape 5 : Ajouter les détails

- Tailles relatives (plus grand = plus important)
- Espacement entre les éléments
- Labels et texte indicatif
- Notes pour le designer/développeur

### Étape 6 : Itérer et valider

- Montrer à quelqu'un d'autre
- Demander : "Tu comprends ce que fait cette page ?"
- Modifier si nécessaire
- Recommencer jusqu'à validation

## Exercice 1 : Wireframe Papier (30 min)

### Objectif
Créer un wireframe low-fidelity pour une app de **taxi-be à Antananarivo**.

### Contexte
L'app permet de :
- Réserver un taxi-be
- Voir les trajets disponibles
- Payer via MVola
- Noter le chauffeur

### Ta mission

1. **Page d'accueil** avec :
   - Recherche de trajet (départ, arrivée)
   - Trajets populaires
   - Bouton de réservation

2. **Page de résultat** avec :
   - Liste des taxis disponibles
   - Prix et durée
   - Bouton de sélection

3. **Page de confirmation** avec :
   - Récapitulatif du trajet
   - Bouton de paiement MVola
   - Confirmation

### Contraintes
- Utiliser uniquement des rectangles et des lignes
- Pas de couleurs
- Noter chaque élément
- Durée : 30 minutes

## Les Erreurs à Éviter

### ❌ Erreur 1 : Trop de détails trop tôt

Ne pas ajouter :
- Les couleurs
- Les vraies images
- Le texte final
- Les icônes détaillées

Le wireframe = Structure, pas décoration !

### ❌ Erreur 2 : Sauter l'étape papier

Aller directement sur ordinateur = :
- Moins créatif
- Plus lent
- Plus difficile à changer

### ❌ Erreur 3 : Ne pas penser au mobile

Aujourd'hui, **la plupart des utilisateurs sont sur mobile** !

Toujours faire :
- Wireframe mobile EN PREMIER
- Wireframe desktop en second

### ❌ Erreur 4 : Faire un seul wireframe

Faire plusieurs options permet de :
- Explorer différentes solutions
- Comparer et choisir la meilleure
- Montrer au client des alternatives

**Conseil** : Faire au moins 3 versions différentes !

## Wireframe Mobile vs Desktop

### Mobile First (Mobile d'abord)

**Pourquoi ?**
- 80% du trafic web à Madagascar est mobile
- Contraintes d'espace forcent à prioriser
- Plus facile d'ajouter que de retirer

**Contraintes mobile :**
- Largeur : 320-414px
- Navigation simplifiée
- Un seul focus par écran
- Gestes tactiles

### Responsive Design

Le même contenu s'adapte à tous les écrans :

```
MOBILE (1 colonne)        TABLETTE (2 colonnes)      DESKTOP (3+ colonnes)
```

## 📝 Quiz: Quiz : Wireframes

**1.** Qu'est-ce qu'un wireframe ?

   ⬜ Un design final avec couleurs
   ✅ Un plan structurel de l'interface
   ⬜ Une photo de l'application
   ⬜ Un code de programmation

*Un wireframe est un plan structurel qui montre la disposition des éléments sans les détails visuels comme les couleurs.*

**2.** Pourquoi est-il préférable de commencer par un wireframe papier ?

   ⬜ C'est plus joli
   ✅ C'est plus rapide à modifier et favorise la créativité
   ⬜ C'est la seule méthode possible
   ⬜ C'est ce que demandent les clients

*Le papier permet d'itérer rapidement, favorise la créativité et peut être facilement jeté et recommencé.*

**3.** Quelle est la différence entre low-fidelity et high-fidelity ?

   ⬜ Low-fi a plus de détails
   ✅ Low-fi est dessiné à la main, High-fi est proche du design final
   ⬜ High-fi est gratuit
   ⬜ Il n'y a pas de différence

*Low-fi (basse fidélité) est un dessin simple, souvent à la main. High-fi (haute fidélité) est très proche du design final avec couleurs et détails.*

**4.** Qu'est-ce que le 'Mobile First' ?

   ⬜ Faire le design desktop en premier
   ✅ Faire le wireframe mobile en premier
   ⬜ Utiliser uniquement un mobile
   ⬜ Ignorer les utilisateurs desktop

*Mobile First signifie concevoir d'abord pour mobile, puis adapter pour les écrans plus grands.*

**5.** Combien de versions de wireframe devrait-on faire au minimum ?

   ⬜ 1 seule version
   ⬜ 2 versions
   ✅ 3 versions ou plus
   ⬜ 10 versions

*Il est recommandé de faire au moins 3 versions différentes pour explorer plusieurs solutions et pouvoir comparer.*
