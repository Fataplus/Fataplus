User Journey - Le Voyage de l’Utilisateur

Introduction

USER JOURNEY = Le voyage de l’utilisateur = L’histoire complète de son expérience

Imagine que tu es un guide touristique. Ton job est d’accompagner les visiteurs du début à la fin de leur voyage. Le User Journey, c’est exactement ça : tracer le chemin que parcourt un utilisateur pour atteindre son but.

Analogie Madagascar 🇲🇬

Pense à un voyage en taxi-be de Analakely vers Antsirabe :

  1. DÉBUT : Tu es à la gare routière, tu cherches le bon taxi
  2. RECHERCHE : Tu demandes “Aiza ny taxi-be mankany Antsirabe?”
  3. ACTION : Tu trouves le taxi, tu montes, tu paies
  4. VOYAGE : 3 heures de route, arrêts, paysages
  5. ARRIVÉE : Tu descends à Antsirabe, content d’être arrivé

Chaque étape compte. Si une étape est mauvaise, tout le voyage est gâché.

Pourquoi le User Journey est important?

Le problème

Les designers oublient souvent ce que ressent l’utilisateur. Ils dessinent des écrans sans penser au parcours complet.

La solution

Le User Journey nous force à : - Voir l’expérience du point de vue de l’utilisateur - Identifier les moments de friction (où ça coince) - Créer des solutions pour chaque étape - Rendre l’expérience fluide et agréable

Les 3 Éléments du User Journey

1. ÉTAPES (Steps)

Les grandes phases du voyage. Par exemple, pour commander sur MVola :

ÉTAPE 1 : Découverte
→ L'utilisateur découvre qu'il peut envoyer de l'argent

ÉTAPE 2 : Inscription
→ Il crée son compte

ÉTAPE 3 : Configuration
→ Il lie son numéro de téléphone

ÉTAPE 4 : Transaction
→ Il envoie l'argent

ÉTAPE 5 : Confirmation
→ Il reçoit la confirmation

2. ACTIONS (Actions)

Ce que fait l’utilisateur à chaque étape :

  • Clique sur un bouton
  • Remplit un formulaire
  • Scrolle la page
  • Prend une photo
  • Parle au support

3. ÉMOTIONS (Emotions)

Ce que ressent l’utilisateur :

😊 Content = Tout va bien 😕 Confus = Ne comprend pas 😤 Frustré = Ça ne marche pas 😰 Anxieux = Peur de faire une erreur 🎉 Soulagé = C’est fait!

Exemple Complet : Tiana utilise MVola pour la première fois

Persona

Tiana = Étudiant de 20 ans, première année à l’université. Il n’a jamais utilisé d’app mobile money.

Comment créer un User Journey

Étape 1 : Définir le persona

Qui fait le voyage ? Utilise les personas créés dans la leçon 1-5 :

  • Ravo (agriculteur, 45 ans)
  • Mamy (mère de famille, acheteuse)
  • Tiana (étudiant, 20 ans)

Étape 2 : Identifier le but

Qu’est-ce que l’utilisateur veut accomplir ?

  • Acheter des légumes sur une app ?
  • Envoyer de l’argent à sa famille ?
  • Réserver un taxi-be ?

Étape 3 : Lister toutes les étapes

Du début à la fin, sans sauter d’étapes !

  • Comment l’utilisateur découvre-t-il le produit ?
  • Quelle est sa première action ?
  • Que fait-il ensuite ?
  • Comment sait-il que c’est terminé ?

Étape 4 : Ajouter les émotions

À chaque étape, demander :

  • Comment se sent l’utilisateur ?
  • Est-ce qu’il est content ? Confus ? Frustré ?
  • Qu’est-ce qui pourrait mal se passer ?

Étape 5 : Identifier les frictions

Les frictions = Les moments où ça coince

Exemples : - Formulaire trop long - Message d’erreur confus - Temps d’attente trop long - Bouton difficile à trouver

Les Outils pour créer un User Journey

Outil 1 : Paper & Pen (Papier et crayon)

Le meilleur outil pour commencer !

  • Dessine une ligne de gauche à droite
  • Ajoute des points pour chaque étape
  • Note les actions et émotions

Outil 2 : Sticky Notes (Post-its)

Parfait pour brainstormer en équipe :

  • 1 post-it = 1 étape
  • Couleurs différentes pour les émotions
  • Facile à réorganiser

Outil 3 : Figma / Miro / FigJam

Pour créer des journey maps numériques :

  • Partageable avec l’équipe
  • Facile à modifier
  • Possibilité d’ajouter des images

Exercice 1 : User Journey de Ravo (30 min)

Contexte

Ravo est un agriculteur de 45 ans à Antsirabe. Il veut utiliser une app pour vendre ses tomates directement aux clients.

Ta mission

Créer le User Journey complet de Ravo :

  1. Définir le but de Ravo
  2. Identifier 5-7 étapes de son voyage
  3. Pour chaque étape :
    • L’action de Ravo
    • Son émotion
    • Une friction potentielle
  4. Proposer 2 solutions pour améliorer son expérience

Format de livraison

Dessine sur papier ou utilise les post-its fournis :

Exercice 2 : Améliorer une expérience (20 min)

Scénario

Tu as identifié ces frictions dans le journey d’un utilisateur qui réserve un taxi-be via une app :

Friction 1 : L’utilisateur ne sait pas où attendre le taxi Friction 2 : Le taxi arrive mais l’utilisateur ne le voit pas Friction 3 : L’utilisateur ne connaît pas le prix avant la fin

Ta mission

Pour chaque friction, propose une solution concrète :

Friction Solution proposée Comment ça aide ?
1. Lieu d’attente
2. Identification taxi
3. Prix inconnu

Temps : 20 minutes en groupe de 2

Les Erreurs à Éviter

❌ Erreur 1 : Sauter des étapes

“L’utilisateur clique et c’est fini !”

Non ! Entre le clic et la fin, il y a : - Le temps de chargement - La confirmation - L’attente - La vérification

❌ Erreur 2 : Ignorer les émotions

Un journey sans émotions = juste une liste de tâches.

Les émotions nous disent où améliorer l’expérience.

❌ Erreur 3 : Ne penser qu’au meilleur scénario

Tout ne se passe pas toujours bien !

Il faut aussi mapper : - Les erreurs possibles - Les problèmes techniques - Les hésitations de l’utilisateur

❌ Erreur 4 : Créer un journey trop complexe

Un bon journey est simple et clair.

  • Maximum 7-8 étapes principales
  • Utilise des sous-journeys si nécessaire
  • Reste focalisé sur UN objectif

User Journey vs User Flow

User Journey

  • Focus : Émotions et expérience
  • Question : “Que ressent l’utilisateur ?”
  • Format : Histoire narrative
  • Usage : Comprendre l’expérience globale

User Flow

  • Focus : Actions et écrans
  • Question : “Que fait l’utilisateur ?”
  • Format : Diagramme technique
  • Usage : Concrétiser le parcours dans l’app

Ils sont complémentaires !

User Journey (Stratégie) → User Flow (Tactique) → Wireframes (Design)

📝 Quiz: Quiz : User Journey

1. Quels sont les 3 éléments principaux d’un User Journey ?

✅ Étapes, Actions, Émotions ⬜ Écrans, Boutons, Textes ⬜ Design, Code, Test ⬜ Utilisateur, App, Serveur

Un User Journey se compose des Étapes (phases), Actions (ce qu’on fait) et Émotions (ce qu’on ressent).

2. Dans le journey de Tiana utilisant MVola, pourquoi est-il anxieux lors de l’inscription ?

⬜ Il ne connaît pas l’app ✅ Le SMS de confirmation met du temps à arriver ⬜ Il n’a pas de crédit ⬜ L’app est lente

Tiana est anxieux car le code SMS met 2 minutes à arriver, ce qui crée une friction dans son expérience.

3. Qu’est-ce qu’une ‘friction’ dans un User Journey ?

⬜ Une étape obligatoire ✅ Un moment où l’expérience est difficile ⬜ Un type d’émotion positive ⬜ Une action répétée

Une friction est un moment où l’utilisateur rencontre une difficulté ou un obstacle dans son parcours.

4. Pourquoi est-il important d’inclure les émotions dans un User Journey ?

⬜ Pour faire joli ✅ Pour identifier les points d’amélioration ⬜ Pour remplir le document ⬜ Ce n’est pas important

Les émotions révèlent les moments où l’utilisateur est frustré ou confus, ce qui nous permet d’améliorer l’expérience.

5. Combien d’étapes principales devrait avoir un bon User Journey ?

⬜ 2-3 étapes ✅ 5-8 étapes ⬜ 15-20 étapes ⬜ Autant que possible

Un bon User Journey a généralement 5-8 étapes principales pour rester clair et focalisé.
